Beats

  1. AyaOpen the booking chooser, pick exact time, choose a station, charger and 60 minutes.
    "She picks how long she needs. Watch the available start times change with it — that is not a stored list, it is worked out from what is genuinely free."
  2. Abdel AzizIn the second browser, request the same charger, same hour. Both press Confirm.
    "Both drivers pressed Confirm. Neither waited for the other."
  3. Abdel AzizHold on the refusal for three seconds. This is the money shot.
    "Refused — and refused by the database itself, not by our code. We split charger time into fifteen-minute blocks and told the database one block has one owner. A rule inside the database cannot be bypassed by a feature somebody writes next year."
  4. Abdel AzizBook 16:00–17:00 on the same charger. It succeeds.
    "A booking ending at four o'clock does not own the four o'clock block. So these two sit back to back with nothing wasted between them."
  5. AyaPay the simulated deposit. Show the QR code.
    "A small deposit confirms it. And I should say clearly — this payment is simulated. No card details are ever entered, stored or shown anywhere."
  6. Abdel AzizType the booking code on /staff, check in, start the session, end it.
    "I can scan her QR with the camera or type the code — both go through exactly the same lookup. And the system has already recorded whether she was early, on time, inside grace, or late. Nobody types that."
  7. Abdel AzizTry to act on Airport. Show the 403.
    "I am assigned to Downtown, so the server refuses. That is not a hidden menu — it is a permission check."

Why it is Malik's: slides 16–17 are the optimizer and reliability, described in his own script as "your strongest material". The counterfactual is his argument to make.

Beats

  1. AyaOpen /book, choose flexible, describe a window: about 30 minutes, any time this afternoon.
    "She is not picking a time. She is describing a window — and that is the whole difference. A wizard can only answer 'which of these exact times?' It has nothing to say when the answer is none of them."
  2. MalikOpen /admin/optimizer. Pause four seconds on the demand pool.
    "The system is not answering one person. It is planning all of them against the same chargers at once. Score people one at a time and two of them will happily be given the same charger."
  3. MalikPoint at the ordering.
    "Least flexible first. If you serve the flexible driver first you can burn the only slot the rigid one could ever have used — and then you serve one customer instead of two."
  4. MalikOpen one assignment's stored rationale.
    "Five things, fixed points each: does it keep the free time in usable blocks, how close to the time they wanted, how long they have waited, priority, and how likely they are to turn up. Same situation, same answer, every time — and this sentence was stored when the decision was made. A manager can show it to a customer."
  5. MalikPause five seconds on the counterfactual. The strongest evidence in the project.
    "Every run also works out what plain first-come-first-served would have achieved on exactly the same data. If we were not better, this number would say so."
  6. AyaShow the offer on /offers with its countdown. Let one expire, then accept late.
    "That charger is genuinely held — nobody else can book it for five minutes, which is what makes pressing Accept safe. And answering late does not throw you out: the system runs again and offers a new time."

21 of the 31 KPIs move during this single recording. That is the reason early departure, extensions and the waitlist are one story instead of three.

Beats

  1. Abdel AzizEnd a 60-minute session after 35 minutes.
    "She booked an hour and left after thirty-five minutes."
  2. AyaPause three seconds on the freed time.
    "Twenty-five minutes just went back on sale. In most systems that time is simply lost — nobody knows it is free."
  3. Show the workers terminal for 8 seconds, then hard cut.
    "These run every minute. Nobody clicks them."
  4. AyaShow the extension top-up landing first.
    "The first refusal went to a driver already charging who had asked for more time. No new arrival, no new deposit, no risk of a no-show — the cheapest customer to serve is the one already in the bay."
  5. AyaShow the waitlisted driver being offered the slot, and the bell.
    "Then the waiting queue. This driver was told 'nothing free' twenty minutes ago and has done nothing since. And the message was not written by the booking code — a separate worker reads the record of what happened, so a message that fails can never break a booking."
  6. AyaThree extension outcomes back to back: approved → partial → rejected, pause four seconds.
    "Room to spare, granted. Only twenty of the thirty minutes actually fit, so she gets twenty and is told why. And refused — because the next customer arrives in ten minutes, and their booking is a promise too."

Beats

  1. Abdel AzizReport a charger failure on /staff/incidents.
    "A charger fails at twenty to four. Four people are booked behind it. The charger goes unavailable immediately — nothing new can land on it."
  2. Abdel AzizShow the delay cascade panel.
    "The system works out which bookings are affected and walks the delay forward — this one, then the one behind it, then the one behind that."
  3. Abdel AzizPause five seconds. The best sentence available to this project.
    "And it has not cancelled anything. It computed the delay, identified who is affected, and stopped. A person decides. We felt cancelling someone's booking should be a human decision, not something a background job does quietly."
  4. MalikShow the refund and the untouched reliability score.
    "Refunded in full — inside the twenty-four hour window, where normally the deposit is kept. Our fault always beats the clock. And their reliability score is untouched, because fault is stamped on the event at the moment it happens. Only staff can set that flag; a driver who could would refund themselves every time."
  5. Abdel AzizOverstay tiers — 12 seconds only.
    "Nobody reported this one. A sweep noticed the session ran past its end. We detect it — we do not yet automatically reserve extra time for it, and that is on our list."

Beats

  2. MalikShow the point table.

Twenty-five clean visits to recover from one no-show — deliberately steep, because a driver who holds a bay and never arrives denies it to someone who would have used it. And a low score never blocks a booking. It only decides who gets the better slot when two people want the same one."
  3. AyaOpen /admin/schedule-quality. Pause four seconds on a sample size.
    "Thirty-one measurements, and every one shows how many cases it is based on. A percentage over three events is not a trend."

    "Where we have no data it says 'no data' — never zero. A zero looks like a real measurement and would mislead."
  5. Terminal: npm run ops:verify — final summary lines only.
    "One hundred and eighty-two automatic checks against a real database, every time we change anything. And they were all passing while half of this dashboard was empty — testing the logic and testing the wiring turned out to be different jobs. That is the lesson we did not expect."

Recording order

Each recording leaves database state the next one needs.
  1. Run ops:verify, capture the 182/182 tail as a still.
  2. Start ops:demo-services and leave it running.
  3. Record V1 — creates the bookings the rest of the day is built around.
  4. Run ops:reconcile, capture "0 disagreements", cut into V1 as a tail.
  5. Record V2 — needs V1's occupancy to make the afternoon genuinely contended.
  6. Record V3 — needs V2's waitlisted driver, or promotion has nobody to promote.
  7. Record V4 — last of the four, so a broken charger cannot disturb V1–V3.
  8. Run ops:verify-demo — confirm 16/16 and no empty KPI section.
  9. Record V5 — every number is now a consequence of what came before.
Never run seed:all, seed:stations or demo -- reset at any point. All three are destructive against the shared database and would erase the state the recordings depend on. Never re-record V1–V4 without re-recording V5.
